# MATLAB analysis guide

This guide follows the actual analysis stages, from configuration to RTN tables
and figures. Run the integrator from the repository root, then inspect each
stage's saved context. The analysis, propagation, statistics, plotting and report
generation all use MATLAB.

For MATLAB installation, license activation, toolbox checks and noninteractive
Windows commands, see [MATLAB setup and terminal execution](MATLAB_SETUP.md).

The comparison measures consistency between a Planet TLE and a published
Cartesian state. Neither product is an independent truth reference. Keep the
run's profile and frame/identity approvals with every reported result.

## Before Stage 00: choose and configure the analysis

### Configure and run the research study

Real orbital evaluation requires MATLAB R2024b or newer, Aerospace Toolbox,
Mapping Toolbox, real source archives and observed Earth-orientation data. From
the repository root, start with the study configuration:

```matlab
startup_consistency
cfg = study_config("research");
% Apply reviewed identity, frame and SGP4 evidence as described in the protocol.
ctx = run_study(cfg);
edit(ctx.latestReportPath)
```

Complete the identity, frame and independent SGP4 reviews in the
[research protocol](RESEARCH_PROTOCOL.md) before running. Research mode rejects
unresolved policies and excludes identities without historical approval. The
report is generated by the run; no precomputed MATLAB research result is supplied.

The supplied configuration covers 1 March through 31 August 2026. Set the
study dates, cohort, roster and paths on `cfg` for another context, and review
leap-second, Earth-orientation and identity coverage for that context.

### Archive paths and offline inputs

The archive root can contain flat files or dated `YYYY/MM/` subdirectories.
For example, `cfg.paths.raw` can point to
`data/planet_ephemerides/raw/daily`, which contains paths such as
`2026/03/planet_20260301.states`. Existing source payloads stay in place.
If the default `data/raw` directory is absent and this dated tree exists,
the configuration selects the dated tree automatically. When using another
cache or a local Earth-orientation file, set `cfg.paths.raw` and
`cfg.paths.eop` explicitly before calling `run_study(cfg)`.

The saved cache contains the study-date archives but not the required EOP file.
For an offline run, provide that file, the dated archives and their guard dates,
and set `cfg.download.enabled = false`. If an identity snapshot is unavailable,
set `cfg.download.snapshotIdentity = false`; matching uses the configured roster.
The archive manifest records selected paths and flags missing sources.
Include one guard date on both sides of the study interval or inspect logged gaps.
Existing receipts are checked against the source payloads; differing flat and
dated copies, invalid receipts and hash mismatches are flagged and excluded.

### Source audit and exploratory pilot

To inspect real sources and pairing before orbital evaluation:

```matlab
startup_consistency
cfg = study_config("audit");
ctx = run_study(cfg); % Stages 00-03; no SGP4 metrics
```

For an exploratory real-data comparison, use `study_config("pilot")` and
`run_study(cfg)`. Pilot mode uses candidate historical identities and an
adopted J2000-to-ICRF interpretation; its results are provisional and do not
satisfy the research approval gates. Configure its dates, paths, EOP and
bootstrap settings on `cfg` before running.

### How to inspect stages without rerunning them

`run_study` executes the numbered scripts in a private function workspace. Each
completed stage creates `stage_NN.mat` containing `snapshot`; later snapshots
include the earlier stage data. Run complete analyses through `run_study`.
Calling individual stage scripts in the base workspace can mix contexts from
different runs.

After the analysis completes, MATLAB attempts to publish a full report at
`results/RUN_REPORT.md`, with links to the run-specific tables and figures. On
success, `ctx.latestReportStatus` is `"PUBLISHED"` and `ctx.latestReportPath` is
the stable path. A completed audit can publish an explicitly labelled audit
report; an empty primary sample is reported as unavailable rather than filled
with earlier results.

If publication fails, MATLAB emits a warning while preserving `RUN_COMPLETE.txt`
and the timestamped original report. Then `ctx.latestReportStatus` is `"FAILED"`,
`ctx.latestReportPath` points to that original, and `REPORT_PUBLISH_FAILED.txt`
in the run directory records the reason. An existing unowned or read-only stable
file is preserved and may describe an older run.

The run's `publication_status.mat` records the final publication result. Stage
checkpoints and `results.mat` are saved before the stable copy is attempted, so
their publication status can still be `"PENDING"`.

After a run, retain its printed output directory:

```matlab
runDir = ctx.runDir;
disp(ctx.latestReportPath)
disp(ctx.latestReportStatus)
disp(ctx.stageLog)
saved = load(fullfile(runDir, "stage_03.mat"), "snapshot");
pairingStage = saved.snapshot;
```

The sections below assume `ctx` is the completed run context. For an earlier
checkpoint, load its `snapshot` into a separate variable and inspect that instead.

## Stage 00: environment, configuration and provenance

**Script:** `scripts/stage00_preflight.m`.

**Inputs:** the configuration, roster path, leap-second table and MATLAB
environment.

Preflight validates dates and settings, checks required functions for real
evaluation, applies research policy gates, and creates a new timestamped run
directory. It records MATLAB/toolbox versions, source-code hash, roster and
leap-table hashes, and the complete configuration. The time window must remain
inside the reviewed leap-table validity.

**Outputs:** `configuration.mat`, `run_manifest.json`, `stage_00.mat`; the run's
stage ledger is written to `stage_log.csv` as processing advances.

```matlab
disp(ctx.cfg.profile)
disp([ctx.cfg.study.startUTC, ctx.cfg.study.endUTC])
manifest = jsondecode(fileread(fullfile(ctx.runDir, "run_manifest.json")));
disp(manifest.matlabVersion)
disp(manifest.sgp4Path)
```

**Review before interpretation:** confirm the intended profile, UTC interval,
cohort and backend. Resolve missing toolboxes, unresolved frame policies or leap
validity errors before trying another live run. An approval flag needs supporting
evidence; it is not a substitute for verification.

## Stage 01: acquire and cache the source products

**Script:** `scripts/stage01_acquire.m`.

**Inputs:** UTC study dates, download/cache settings, Planet archive base URL and,
for live metrics, the configured Earth-orientation source.

The downloader requests both products for every study date plus one guard date
on each side. Three study dates therefore require ten dated `.states`/`.tle`
archives, with identity and EOP snapshots acquired separately when configured.
Existing cache payloads are reused without replacement. SHA-256 provenance
sidecars allow a later cache change to be detected.

**Outputs:** local raw/auxiliary files, their provenance sidecars,
`archive_manifest.csv` and `stage_01.mat`.

```matlab
disp(ctx.manifest(:, {'Kind','ArchiveDateUTC','Status','Bytes','LocalPath'}))
available = ismember(ctx.manifest.Status, ["CACHED", "DOWNLOADED"]);
disp(ctx.manifest(~available, {'SourceURL','Status','Message'}))
```

**Review before interpretation:** investigate `MISSING_OFFLINE`,
`DOWNLOAD_FAILED` and `CACHE_HASH_MISMATCH`. A pipeline can finish with incomplete
source coverage; `RUN_COMPLETE.txt` does not certify that every archive exists.
Do not substitute a current file for a missing historical date. A missing EOP
file must be resolved before the real ground metric can be evaluated.

## Stage 02: parse, reconcile time and clean repeated records

**Script:** `scripts/stage02_preprocess.m`.

**Inputs:** successful source-manifest entries, the configured roster and leap
table.

Cartesian positions and velocities remain in metres and metres per second. The
parser preserves the published TT-seconds text and native TLE lines; TLE checksums
and fields are validated. Native times become integer TT nanoseconds relative to
J2000 TT. Eligibility therefore avoids subtracting large floating-point Julian
dates. Printed source resolution is audited separately from epoch separation.

Identical normalized payloads collapse to one record with all archive occurrences
retained. Different payloads at one identity/native epoch are flagged as
conflicting revisions and excluded from pairing until resolved. The roster must
match the configured flock.

**Outputs:** `states.csv`, `tles.csv`, `parse_log.csv`, `record_occurrences.csv`,
`roster_used.csv`, `time_precision_audit.csv` and `stage_02.mat`.

```matlab
disp(ctx.timeAudit)
disp(ctx.parseLog)
disp(ctx.states(ctx.states.Revision, {'HWID','EpochUTC','Status'}))
disp(ctx.tles(ctx.tles.Revision, {'CatalogID','EpochUTC','Status'}))
```

**Review before interpretation:** distinguish records outside the target cohort
from malformed target data; inspect the source line and error message. Resolve
relevant parse failures or revisions before claiming coverage. Integer storage
preserves serialized resolution; it does not imply nanosecond physical orbit
knowledge. Rejected leap-second instants or time-precision failures need an
explicit processing decision, not manual adjustment of epochs.

## Stage 03: match identities and select daily epoch pairs

**Script:** `scripts/stage03_pair.m`.

**Inputs:** cleaned native records, roster identity-validity intervals, and primary
and sensitivity time tolerances.

For each Cartesian record whose native UTC date is in the study window, the
pairer requires a unique roster identity interval, a matching catalogue number,
and a corroborating TLE-header HWID. Research also requires the historical
identity approval. It chooses the nearest eligible native TLE, preferring the
earlier TLE epoch on an exact tie. It then retains the latest eligible Cartesian
epoch per satellite/UTC day.

The primary tolerance is inclusive at **1 ms**. The **24-hour sensitivity** is
selected independently. Wider-window pairs never fill missing primary pairs;
selection does not use residual magnitude. Guard archives support boundary
matching without enlarging the Cartesian study interval.

**Outputs:** primary/sensitivity candidate-decision tables and pair tables,
`coverage.csv` and `stage_03.mat`. Audit mode ends here and writes its audit
`RUN_REPORT.md`.

```matlab
disp(ctx.coverage)
disp(groupsummary(ctx.primaryCandidates, "Status"))
disp(ctx.primary(:, {'Satellite','DateUTC','DeltaTime_ns','IdentityVerified'}))
assert(all(abs(ctx.primary.DeltaTime_ns) <= ctx.cfg.pairing.primaryTolerance_ns))
```

**Review before interpretation:** explain zero-pair satellites, rejected identities
and time-window exclusions. The latest published/archive record need not be an
eligible daily pair. Distinguish satellite-days, unique payloads and repeated
archive occurrences. At most one accepted primary pair per satellite/day does
not make adjacent days statistically independent.

## Stage 04: evaluate the selected TLE and prepare a common frame

**Script:** `scripts/stage04_evaluate_sgp4.m`.

**Inputs:** the union of the independently selected pair samples, original TLE
records, Cartesian states and the adopted frame policy.

For real data, each selected TLE is isolated in its own file before `tleread` so
historical records cannot be replaced by a newer catalogue entry. The code checks
catalogue identity, native `BStar`, epoch precision, UTC round-trip precision and
the near-Earth regime. MATLAB `propagateOrbit` evaluates SGP4 at the paired
Cartesian epoch with ICRF output. The Cartesian vector is prepared using the
configured full-state mapping. No fitted correction, drag/SRP override or
Cartesian propagation is introduced.

**Outputs:** `evaluated_states.csv`, `selected_tles/` for real selected payloads,
and `stage_04.mat`.

```matlab
disp(groupsummary(ctx.evaluations, "Status"))
failed = ctx.evaluations.Status ~= "OK";
disp(ctx.evaluations(failed, {'PairID','Status','Message'}))
disp(ctx.evaluations(:, {'UTCroundTrip_ns','ParsedEpochDifference_ns','FramePolicy'}))
```

**Review before interpretation:** investigate failed propagation, identity,
`BStar` or epoch gates. A low discrepancy cannot justify a frame policy. Pilot
frame assumptions and unverified SGP4 status must remain attached to results;
research requires the evidence described in the protocol.

## Stage 05: calculate vector, signed RTN and ground discrepancies

**Script:** `scripts/stage05_metrics.m`.

**Inputs:** successful prepared states, pair membership and the configured
inertial-to-Earth-fixed transformation/EOP data.

The inertial differences are **TLE minus Cartesian**. Position and velocity
metrics are three-dimensional vector norms. The Cartesian state defines the
position RTN basis:

```text
dr = r_TLE - r_Cartesian
dv = v_TLE - v_Cartesian
R = r_Cartesian / ||r_Cartesian||
N = (r_Cartesian x v_Cartesian) / ||r_Cartesian x v_Cartesian||
T = N x R
[dR; dT; dN] = [R'; T'; N'] * dr
```

Positive R is outward, positive N follows orbital angular momentum, and positive
T is transverse in the forward orbital direction. RTN fields are signed position
components in metres; velocity remains an inertial vector difference.

For real ground separation, both simultaneous positions use the same observed
EOP rotation and WGS84 ellipsoid-normal footpoints. For a spacecraft outside the
ellipsoid, the footpoint is the nearest ellipsoid point, along its surface normal;
it is generally different from the geocentric radial intersection. This is the
same geodetic-latitude/longitude and zero-height convention documented for
Skyfield's `wgs84.subpoint_of`, though numerical cross-backend agreement has not
been verified. The current implementation is MATLAB. The surface metric compares
the two footpoints, not complete orbital tracks. No EOP extrapolation or automatic
zero-EOP fallback is used.

The ground report also resolves that surface distance in geographic directions.
At the Cartesian-derived footpoint, use the inverse-geodesic distance `d` and
forward azimuth `az` towards the TLE footpoint, clockwise from north:

```text
GroundEast_m  = d * sin(az)     positive east
GroundNorth_m = d * cos(az)     positive north
hypot(GroundEast_m, GroundNorth_m) = Ground_m
```

Azimuth is undefined for coincident footpoints, whose east/north components are
both zero. These are geodesic distance-and-bearing components on the ellipsoid,
not an image-target displacement or orbital RTN components. In particular,
geographic north is different from the RTN normal direction. The origin sets
the sign convention and does not designate the Cartesian product as truth.

**Outputs:** `paired_residuals.csv`, decoded EOP/hash outputs for the real IERS
mode, and `stage_05.mat`.

```matlab
R = ctx.residuals(ctx.residuals.IsPrimary & ctx.residuals.Status == "OK", :);
disp(R(:, {'Satellite','DateUTC','Radial_m','Transverse_m','Normal_m','Ground_m'}))
disp(R(:, {'Satellite','DateUTC','LatC_deg','LonC_deg', ...
    'GroundEast_m','GroundNorth_m','GroundAzimuth_deg'}))
disp(ctx.residuals(ctx.residuals.Status ~= "OK", {'PairID','Status','Message'}))
```

**Review before interpretation:** a failed ground conversion excludes that pair
from joint summaries even if its state/RTN fields were computed. Those fields
and the failure remain in the residual table. Always distinguish selected pairs
from successful metric pairs; failures never become zero discrepancy.

## Stage 06: summarize results and assess uncertainty

**Script:** `scripts/stage06_summarize.m`.

**Inputs:** residuals with successful state and ground metrics, sample membership,
roster, study dates and bootstrap settings.

Primary, full 24-hour and asynchronous-only summaries remain separate. The code
produces pooled, satellite and month groups, plus primary satellite-month groups,
equal-satellite RMS sensitivity, first-pair-per-ISO-week thinning and
leave-one-month-out summaries.
The ground east/north components use the same successful pairs for signed mean,
sample SD and RMS. Their squared component RMS values sum to the squared ground
distance RMS. Opposing geographic offsets can cancel in a pooled signed mean;
inspect the component plots and satellite/date distributions alongside it.

For the same N successful pairs:

```text
Component mean = sum(component) / N
Component SD   = sqrt(sum((component - mean)^2) / (N - 1))
Component RMS  = sqrt(sum(component^2) / N)
3D RMS         = sqrt(sum(||dr||^2) / N)
3D RMS^2       = RMS_R^2 + RMS_T^2 + RMS_N^2
```

There is no division by three. SD is unavailable for N=1. Percentiles use type-7
linear interpolation. An empty group retains N=0 and unavailable statistics.
Equal-satellite weighting applies to RMS quantities only and has a distinct
estimand from pair weighting.

When enabled, moving-block bootstrap resamples calendar-date blocks with all
satellites on a date moving together; empty dates remain in the calendar. Full
study defaults use 7-day blocks and 2,000 replicates with 3/14-day sensitivity.
Short windows cannot meet the configured minimum date support. Missing support
or too few valid replicates yields an explicit unavailable interval, not a
replacement estimate. Intervals concern summary statistics and are not orbit
covariance.

**Outputs:** `ctx.summaries`, `ctx.intervals` and `stage_06.mat`; Stage 07 exports
their CSV tables.

```matlab
A = ctx.summaries;
pooled = A.Sample == "primary_1ms" & A.Grouping == "pooled" & A.Weighting == "pair";
disp(A(pooled, {'N','DistinctDates','Satellites','RMS_Position_m','Mean_R_m','Mean_T_m','Mean_N_m'}))
disp(ctx.intervals)
```

**Review before interpretation:** record N, distinct dates and represented
satellites alongside every result. Examine changes across satellite/month groups
before interpreting a pooled mean. Bootstrap status and stationarity assumptions
matter; setting a larger replicate count cannot repair insufficient dates.

## Stage 07: export, plot and interpret the analysis

**Script:** `scripts/stage07_export.m`.

**Inputs:** the complete context, summary/interval tables and reporting settings.

The exporter writes a run report with actual sample counts and RTN results,
reusable numerical tables and labelled figures. PNGs have editable MATLAB FIG
companions. Each marker in a daily plot is a successful primary satellite/day
pair; omitted dates are not interpolated into a reference orbit. SD bars show
sample scatter, not uncertainty of the mean.

**Outputs to read first:**

| File | Analysis use |
|---|---|
| `results/RUN_REPORT.md` | Latest successfully published run report with links to its actual run folder |
| `<run>/RUN_REPORT.md` | Stage explanations, run assumptions, sample counts, results and figure links for that run |
| `table3_coverage.csv` | Full-roster coverage, including zero-pair satellites |
| `table4_pooled_state_ground.csv` | Primary pooled position, velocity and ground statistics |
| `table5_rtn_pooled.csv` | Pooled R/T/N signed mean, sample SD and RMS |
| `table5_rtn_all_groups.csv` | Component statistics by pooled/satellite/month/satellite-month group |
| `table6_ground_en_pooled.csv`, `table6_ground_en_all_groups.csv` | Ground east/north signed mean, sample SD and RMS |
| `ground_daily_summary.csv`, `ground_satellite_summary.csv` | Ground-distance RMS and distribution summaries by UTC date/satellite, with N |
| `summary_all.csv` | Separate sample, weighting, weekly and omitted-month results |
| `bootstrap_intervals.csv` | Requested intervals, valid replicate counts and support status |
| `failed_evaluations.csv`, `failed_metrics.csv` | Explicit exclusions to investigate |
| `figures/rtn_daily.png`, `figures/rtn_summary.png` | Signed RTN by date and pooled component mean/SD/RMS |
| `figures/ground_en_scatter.png`, `figures/ground_en_daily.png` | Geographic east/north components in metres, jointly and by UTC date |

| `results.mat`, `stage_07.mat`, `stage_log.csv` | Saved run context, final stage snapshot and execution ledger |

```matlab
disp(fileread(ctx.latestReportPath))
disp(fileread(fullfile(ctx.runDir, "RUN_REPORT.md")))
RTN = readtable(fullfile(ctx.runDir, "table5_rtn_pooled.csv"), 'TextType', 'string');
disp(RTN)
groundEN = readtable(fullfile(ctx.runDir, "table6_ground_en_pooled.csv"), 'TextType', 'string');
disp(groundEN)

if ctx.cfg.reporting.figures && hasPrimary
    openfig(fullfile(ctx.runDir, "figures", "rtn_summary.fig"), 'new', 'visible');
    openfig(fullfile(ctx.runDir, "figures", "ground_en_scatter.fig"), 'new', 'visible');
end
```

`RUN_COMPLETE.txt` means the configured stages finished. Assess source coverage,
per-pair failures, identity/frame evidence and interval support separately before
accepting a scientific interpretation. A dominant component describes the
observed relative discrepancy; it does not identify a physical error source or
certify either product's accuracy.

The coordinate figure is shown before the ground-distance and RMS figures. It
uses the most represented satellite by default (lexical name breaks ties); set
`cfg.reporting.groundPlotSatellite` to an exact represented satellite name to
choose another. Both products can overlap at degree scale; use the signed
east/north metre plot to see their smaller separation. The points are daily
samples, not an interpolated ground track. A daily RMS uses only pairs available
on that UTC date; when N=1 it equals the single distance.

Use only tables and figures produced by the current MATLAB run when reporting
MATLAB results. Previously generated external-backend examples are historical
artifacts and are not evidence of MATLAB execution. MATLAB runtime validation
was unavailable during the documentation update; run `run_tests` locally before
using the MATLAB pipeline for a live analysis.

## Inspect a failed run and repeat it reproducibly

If a stage throws an error after a run directory is created, inspect
`RUN_FAILED.txt`, `failed_context.mat`, `stage_log.csv`, and the last completed
`stage_NN.mat`. Individual propagation/metric failures are logged per pair and
may not stop the stage.

```matlab
runDir = fullfile(pwd, "results", "YOUR_RUN"); % Use the directory printed by this run.
disp(fileread(fullfile(runDir, "RUN_FAILED.txt")))
saved = load(fullfile(runDir, "failed_context.mat"), "failedContext");
failed = saved.failedContext;
disp(failed.cfg.profile)
disp(failed.stageLog)
```

Correct the configuration, cache or processing issue, then start a new complete
run. Checkpoints are inspection artifacts; changing settings and running a later
script against an earlier context is not a reproducible continuation. Every
normal run creates a fresh directory so successful and failed runs remain
distinguishable.

MAT files preserve native int64 epochs. When importing CSV epoch columns, keep
them as text or int64 instead of converting them to floating-point spreadsheet
values. Retain the manifest and source hashes with shared tables and figures.

[data dictionary](DATA_DICTIONARY.md) for column definitions, and the
[research protocol](RESEARCH_PROTOCOL.md) for the full study and approval gates.
